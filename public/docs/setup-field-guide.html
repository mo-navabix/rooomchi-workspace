راهنمای فیلدهای ویزارد راه‌اندازی اولیه (Setup)

سامانه روم‌چی — نسخه راهنما برای نصب self-hosted · مسیر: /setup

این سند توضیح می‌دهد هر فیلد در مراحل راه‌اندازی اولیه برای چه استفاده می‌شود. پس از اتمام ویزارد، بسیاری از این تنظیمات از بخش «مدیریت و تنظیمات سازمان» هم قابل تغییر است.

نکته: مراحل SMTP و ذخیره‌سازی اختیاری‌اند؛ می‌توانید خالی بگذارید و بعداً تکمیل کنید. مرحلهٔ احراز هویت را مطابق سیاست IT سازمان انتخاب کنید.

مرحله ۱ — پیکربندی سازمان

نام سازماننام رسمی شرکت یا واحد که در پورتال و گزارش‌ها نمایش داده می‌شود. الزامی.
کد سازمانشناسه کوتاه یکتا (مثلاً DEMIS). برای تفکیک tenant، لینک ورود و یکپارچه‌سازی‌ها استفاده می‌شود. الزامی.
دامنه شرکتدامنه ایمیل سازمان (مثلاً company.com)؛ برای اعتبارسنجی دامنه Google و تنظیمات SSO. الزامی.
ایمیل شرکتایمیل تماس رسمی سازمان (پشتیبانی، اعلان‌های سیستمی). الزامی.
منطقه زمانیمنطقه IANA (مثلاً Asia/Tehran) برای زمان جلسات، رزرو و گزارش‌ها.
کشورکشور محل استقرار؛ در تنظیمات محلی و گزارش‌ها استفاده می‌شود.

مرحله ۲ — مدیر اول سیستم

اولین کاربر با دسترسی کامل (Super Admin سازمان) ساخته می‌شود.

نام کاملنام نمایشی مدیر در پورتال. الزامی.
ایمیلایمیل ورود و دریافت اعلان‌ها. الزامی.
نام کاربریشناسه ورود (در کنار ایمیل). الزامی.
رمز عبورحداقل ۸ کاراکتر؛ پس از نصب قابل تغییر از پروفایل. الزامی.
تأیید رمز عبورباید با رمز عبور یکسان باشد. الزامی.

مرحله ۳ — احراز هویت

گزینه‌های کلی

ورود محلیورود با ایمیل/نام کاربری و رمز ذخیره‌شده در روم‌چی. معمولاً برای شروع فعال است.
ثبت‌نام خودکار پرسنلاگر فعال باشد، کاربران جدید می‌توانند خود ثبت‌نام کنند؛ در غیر این صورت فقط دعوت/ایجاد توسط ادمین.
LDAP / ADورود از Active Directory یا LDAP سازمان؛ فیلدهای اتصال در صورت فعال‌سازی الزامی‌اند.
Google OAuthورود با Google Workspace؛ نیاز به Client ID و Secret از کنسول Google.

فیلدهای LDAP (در صورت فعال‌سازی)

LDAP URLآدرس سرور، مثلاً ldap://dc.company.local:389
Bind DNکاربر سرویس برای جستجو در دایرکتوری
Bind Passwordرمز حساب Bind
Base DNریشه جستجوی کاربران، مثلاً DC=company,DC=local
User filterالگوی جستجو؛ {username} با ورودی کاربر جایگزین می‌شود

فیلدهای Google OAuth

Client IDشناسه OAuth از Google Cloud Console
Client Secretرمز محرمانه OAuth
Redirect URLآدرس بازگشت؛ معمولاً https://دامنه-شما/api/auth/google/callback

مرحله ۴ — SMTP (اختیاری)

برای ارسال ایمیل دعوت، اعلان رزرو و یادآوری. اگر Host خالی باشد، این مرحله رد می‌شود.

Hostآدرس سرور SMTP
Portپورت (معمولاً 587 TLS یا 465 SSL)
Username / Passwordاعتبار SMTP
From Emailآدرس فرستنده در ایمیل‌های خروجی
From Nameنام نمایشی فرستنده

مرحله ۵ — ذخیره‌سازی فایل

مسیر آپلود (Local)پوشه روی سرور برای لوگو و فایل‌های آپلودی (پیش‌فرض ./uploads). در نسخه‌های بعد S3/MinIO پشتیبانی می‌شود.

مرحله ۶ — بازبینی و اتمام

خلاصه تنظیمات را بررسی کنید. با «Complete Installation» سازمان، ادمین و تنظیمات در دیتابیس ثبت و ویزارد بسته می‌شود؛ ورود با حساب مدیر ایجادشده فعال است.
